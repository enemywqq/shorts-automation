# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Оркестратор-конвейер: исходное видео → вертикальные клипы → очередь в SQLite → заливка в TikTok с отложенной публикацией. Свой код только в `app/`. Два внешних инструмента лежат в `tools/` как git submodules. Их вызываем исключительно через `subprocess`, у каждого свой `.venv`. Код сабмодулей не правим. Единственное исключение: патч генератора `patches/shorts-generator.patch`.

Пожелания владельца: минимально рабочее решение, без лишних абстракций, все настройки в одном файле ([app/config.py](app/config.py)), только stdlib. Общение, комментарии в коде и сообщения CLI — на русском. Уведомления в Telegram запланированы на самый конец, пока их не трогать.

## Навыки (обязательно)
- Любой код: используй навык ponytail.
- Ответы мне в чате: используй навык caveman.
- Любой текст, который остаётся в проекте (README, документация, комментарии, сообщения коммитов, подписи к видео): прогоняй через навык humanizer.
- Никогда не используй точку-разделитель между словами ("·") ни в каком тексте.

## Правила кода
- Без оверинжиниринга. Минимальное решение, которое работает в реальном сценарии. Никаких абстракций, классов и слоёв «на будущее».
- Не трогай tools/ (сабмодули). Если без правки внутри них не обойтись, сначала спроси. Согласованные правки генератора живут только в `patches/shorts-generator.patch`: поправил файл сабмодуля, значит, пересобери патч (`git -C tools\shorts-generator diff --output=..\..\patches\shorts-generator.patch`).
- После обновления сабмодуля генератора проверь, что патч применяется к чистому сабмодулю: `git -C tools\shorts-generator apply --check ..\..\patches\shorts-generator.patch`. Если не применяется, сначала спроси, как переносить правки.
- Чужие инструменты вызываем только через subprocess с python из их собственного .venv. Не импортируем их код в наш.
- Пути только через pathlib, без хардкода абсолютных путей. Всё настраиваемое лежит в одном конфиге, секреты в .env, в код их не пишем.
- Не добавляй новые зависимости без моего согласия.
- Type hints в сигнатурах функций. Функции короткие, одна задача на функцию.
- Ошибки не глотаем: никаких голых except. Ошибку внешнего инструмента логируем вместе с его stderr и записываем в БД.
- Заливку со статусом unknown («возможно, опубликовано») никогда не повторяем автоматически.
- Логи (ход работы, ошибки, предупреждения) через logging. Вывод, который команда показывает пользователю как результат (таблица status, итоговые сообщения), через print.
- Комментарии только там, где неочевидно «почему». «Что делает код» не комментируем.

## Коммиты
Формат Conventional Commits: `тип(область): описание`

Типы:
- feat: новая функциональность
- fix: исправление ошибки
- refactor: изменение кода без изменения поведения
- docs: документация
- chore: настройки, зависимости, сабмодули, мелкие служебные правки
- test: тесты

Область указывает, какую часть проекта затрагивает коммит: queue, upload, process, config, db, cli, readme, tools. Если коммит затрагивает весь проект, область не пишем.

Описание:
- на русском, с маленькой буквы, без точки в конце, до 72 символов;
- пишем, что сделано, а не что нужно сделать: «добавлена», «реализован», «исправлена», «удалён». Нельзя: «добавить», «сделать», «TODO»;
- без длинных тире, без эмодзи, без канцелярита и пустых слов вроде «улучшен код» или «небольшие правки».

Если одной строки мало, после пустой строки идёт тело: коротко, почему сделано именно так. Что именно изменилось, видно в диффе, это не пересказываем.

Примеры:
feat(upload): реализована заливка с отложенной публикацией через -sc
fix(process): исправлена перезапись клипов при повторном запуске
refactor(db): статусы клипов вынесены в константы
docs(readme): добавлена инструкция по тестовому прогону
chore(tools): обновлён сабмодуль tiktok-uploader

fix(upload): клип помечается unknown до вызова аплоадера

Если процесс прервётся посреди заливки, клип не уйдёт повторно
автоматически и не создаст дубль.

## Команды

Windows, PowerShell, из корня проекта. Своего venv у оркестратора нет.

```powershell
py -3.13 -m app process <путь|URL>   # генератор → перекодирование в H.264 → строки в БД
py -3.13 -m app cut [<путь|URL>]     # то же в data/preview, без БД; открывает папку; cut.bat вызывает это
py -3.13 -m app upload               # все pending → свободные слоты → autotok с -sc
py -3.13 -m app status
py -3.13 -m app retry <id> [<id>...] # только failed/unknown → pending
```

Тестов и линтера нет. Логику без реального TikTok проверяют так: в скрипте-обёртке подменяют `config.DB_PATH`, `config.CLIPS_DIR`, `config.GENERATOR_DIR`/`GENERATOR_PYTHON` и `config.UPLOADER_DIR`/`UPLOADER_PYTHON` на временную папку с фейковыми `main.py` и `cli.py`, а `reencode` подменяют на копирование файла.

Установка инструментов описана в [README.md](README.md). Инструменты вызываются как `tools\<tool>\.venv\Scripts\python <entry>` без активации venv.

## Архитектура и неочевидные связи

**Генератор** (`tools/shorts-generator`, `main.py --mode local`):
- Режим по умолчанию у него `api` (платный MuAPI), поэтому `--mode local` передаётся всегда.
- Запускается с `cwd=GENERATOR_DIR`. Папку вывода задаёт env `LOCAL_OUTPUT_DIR` — она перекрывает его `.env`, потому что `load_dotenv` вызывается без override.
- Папка вывода `data/clips/<source_id>/` передаётся **относительным путём от cwd генератора**, а `source_id` намеренно ASCII. Причина: путь к проекту содержит кириллицу, а OpenCV в генераторе на Windows ненадёжно открывает не-ASCII пути.
- `clip_url` в `result.json` тоже относителен cwd генератора.
- Если отдельный клип не собрался, у него `clip_url: null`, а код выхода всё равно 0.
- OpenCV пишет видео в mp4v, поэтому каждый клип перекодируется ffmpeg в H.264/AAC (`short_NN_h264.mp4`), а исходный файл удаляется.
- В том же вызове ffmpeg вжигаются субтитры и заголовок: из `<исходник>.srt` генератора вырезается кусок по `start_time`/`end_time`, всё пишется во временный `.ass` (PlayRes 1080x1920). ffmpeg запускается с cwd в папке клипа и получает `ass=<имя>` без пути, потому что двоеточие в `C:\` ломает синтаксис фильтров.
- Патч генератора (`patches/`) даёт запросам к Gemini таймаут 2 минуты и 5 попыток. Без него google-genai ждёт вечно и не повторяет 503. Кроме того, кадрирование ищет лицо раз в 5 кадров на копии шириной 320 px, а нарезка ставит `-ss` до `-i`.
- `HIGHLIGHTS_TIMEOUT` в конфиге страхует от зависания: оркестратор убивает генератор, если выбор моментов идёт дольше. Конец этапа определяется по строкам вывода генератора (`GENERATOR_STAGES`). Если генератор поменяет эти строки, замер этапов и таймаут перестанут срабатывать.
- `GEMINI_MODEL=gemini-3.5-flash-lite` в `.env` генератора: полные flash-модели часто отвечают 503 high demand.
- В venv генератора закреплены `av==18.1.0` и `opencv-python<5` (причины в README). Если в `result.json` у клипов `WinError 32` про `.cut.mp4`, это маска: настоящая ошибка произошла внутри кадрирования OpenCV.

**Аплоадер** (`tools/tiktok-uploader`, `cli.py upload`):
- Это autotok 2.x. Node.js не нужен, сессии лежат в `~/.autotok/accounts`.
- `-sc` — секунды от текущего момента. Расписание держит сам TikTok, постоянно работающего планировщика нет.
- Коды выхода: 0 — успех, 2 — ошибка валидации, 1 — прочие ошибки.
- Ошибку `PublishUncertainError` (пост мог уйти) распознаём только по подстроке `check the account` в выводе (`UNCERTAIN_MARKER`). Если autotok поменяет текст этой ошибки, детекция сломается.

**Очередь** — одна таблица `clips`, статусы `pending`/`uploaded`/`failed`/`unknown`:
- Слот назначается в момент `upload`, а не при `process`.
- Занятыми считаются слоты клипов в статусах `uploaded` и `unknown`; `failed` слот освобождает.
- Перед вызовом аплоадера строка заранее ставится в `unknown`. Так прерванная заливка не повторится сама. Traceback в выводе тоже даёт `unknown`.
- **`unknown` никогда не ретраится автоматически**, только вручную через `retry`. Это инвариант против дублей постов.
- Повторный `process` того же исходника (абсолютный путь или URL) — no-op.

**Время**:
- `TZ` — фиксированный сдвиг UTC+10 (Владивосток), а не `ZoneInfo`: на Windows `ZoneInfo` требует пакет tzdata.
- `MIN_LEAD` = 20 минут: минимум TikTok 15 минут плюс запас на заливку. Без запаса autotok сам сдвинет публикацию с границы слота.
- `MAX_LEAD` = 10 дней: части аккаунтов TikTok не даёт планировать дальше.
- Запланированное видео не может быть приватным, поэтому любой тест `upload` — это настоящий публичный пост.
